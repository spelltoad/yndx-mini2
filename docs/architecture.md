# Архитектура quasar и границы расширения

Статус: проверенная основа + явно маркированные upstream-механизмы. Локальные свидетельства: [E01–E03](evidence/001-inventory.md), [E07–E08](evidence/003-modifications.md), [E09–E10](evidence/004-architecture.md). Будущие варианты: [модульная модель](extension-model.md).

## 1. Слои

```text
Bootloader / kernel 4.9.68 aarch64
└─ Buildroot, BusyBox init; системные бинарники ELF32 ARM
   ├─ rcS → init.d/S??*                         [observed]
   │  ├─ S99quasar → onboot.sh                 [observed]
   │  │  └─ run.sh → quasar_launcher2          [observed, E11]
   │  │     └─ maind в нескольких ролях        [observed частично]
   │  ├─ S99yam → yamd v0.1.18                 [observed]
   │  └─ S99zdropbear → SSH                    [observed; доступ в private]
   ├─ ALSA, D-Bus, Wi-Fi/Bluetooth, DNS         [observed частично]
   └─ /data: сторонний софт и изменяемое состояние
      ├─ /data/opt/entware ← /opt               [observed]
      ├─ /data/opt/bin/yse                     [observed]
      └─ /data/quazar/yam/data/plugins          [observed, пуст]
```

Не является схемой готового расширения: сейчас LLM и AirPlay не установлены по сведениям владельца; полный поиск всех возможных бинарников не проводился.

## 2. Загрузка и управление жизненным циклом

Локально проверены inittab, rcS, S99quasar, S99yam, S99zdropbear. В пределах rcS файлы S99quasar, S99yam, S99zdropbear идут в таком порядке, но **порядок старта не гарантирует готовность** звука, сети или API. Будущий модуль обязан иметь отдельные readiness checks и ограниченные тайм-ауты, не бесконечный sleep/restart loop.

Локальные onboot.sh/run.sh/q прочитаны с отдельного разрешения: [E11](evidence/005-led.md). onboot.sh меняет overcommit, удаляет OTA-остатки, настраивает окружение/permissions, вызывает сетевые/временные helpers, activate_adb.sh check, q save-last-monotonic-time и run.sh. run.sh запускает quasar_launcher2 по launch.json с cwd /data/quasar, LD_LIBRARY_PATH=/system/vendor/quasar/libs, CA_CERTIFICATES и лимитами -n 10240/-s 1024; вывод в launcher2.out. Содержимое дочерних helpers не проверено.

`q` — не read-only wrapper. Локальный q stop принудительно завершает maind/begemot после остановки launcher. **q getprop создаёт /data/quasar/props, затем читает и удаляет файл**. backend-dev/backend-prod меняют флаг и перезапускают стек. Прочитанные функции не исполнялись; информационное имя команды не разрешает её запуск.

## 3. maind и IPC

Локально maind — ELF32 ARM; наблюдены аргументы --platformd, --mediad, --telemetry. Это не утверждение, что других ролей/подсервисов нет. Upstream описывает также logging и OTA-роли; updatesd в нашем launch.json отсутствует после OTA-модификации.

`led_util`, `tcp_alsa_writer`, `quasar_client` локально ссылаются на maind. Одна ссылка не делает соответствующий интерфейс стабильным или безопасным. ABI, argv и протокол каждого интерфейса ещё требуют исследования.

Upstream различает:

- локальные внутренние сервисы quasar (TCP loopback и IPC);
- glagol — сетевой API, ожидаемый порт 1961;
- uniproxy — речевой канал с облачным backend;
- YAM API — сторонняя надстройка, не часть заводского quasar.

Эти интерфейсы нельзя считать взаимозаменяемыми. На устройстве найдены внутренние loopback listeners и wildcard :1961/:8099, но содержимое протоколов и владельцы портов этим не установлены. Схемы IPC и версия protobuf ещё не подтверждены для нашей сборки.

## 4. Звуковой тракт экземпляра

```text
ALSA default playback
 → softvol "Master Playback Volume"
 → dmix_spk_plug (plug)
 → dmix_spk (dmix, IPC key 1024)
 → hw:0,0 (TDM-B-sy6045s-hifi)

ALSA default capture
 ← multi: четыре выбранных канала hw:0,1 (PDM)
        + два канала hw:0,0 (loopback)
```

Это **статическая конфигурация**, не запись звука и не проверка реального аудиопотока. Физический микрофонный массив и параметры VQE отдельно не проверялись. Частоту 48 кГц из рецепта другой модели не считать измеренной на нашей.

Ключевое ограничение пакетов: aarch64-ядро допускает отдельное 64-битное окружение, но сторонняя 64-битная alsa-lib не обязана делить dmix с системной 32-битной. Upstream AirPlay описывает такие конфликты на Лайт 2. Будущий аудиомодуль должен объявлять loader/libc/alsa-lib, ALSA_CONFIG_PATH и стратегию владения PCM. Нельзя глобально менять LD_LIBRARY_PATH для всех программ.

## 5. Речь и LLM — пока upstream

```text
микрофоны + loopback
 → локальные VQE / spotter
 → uniproxy → облачный ASR / обработка диалога
 → директивы / TTS → локальный вывод
```

Общая голосовая страница описывает локальные wake-word/короткие команды и облачный ASR. Настройки withLocalVins, VQE и маршруты uniproxy **на нашем экземпляре пока не прочитаны**. Не обещать получение распознанного текста без облака или доступ к очищенному микрофону на Мини 2 по примеру Plum.

**Кастомный промпт — не один системный файл Алисы.** Он принадлежит выбранному LLM-адаптеру/прокси. Изменение backendUrl не равно перенаправлению речевого uniproxy. Подмена endpoints затрагивает облачную авторизацию, TLS, приватность и отказоустойчивость; требует отдельной спецификации и разрешения.

Заявление страницы gotchas «пиннинга нет» не доказывает ни отсутствие TLS-проверки, ни доверие произвольному сертификату. Поддержка ws:// и отсутствие certificate pinning — разные свойства. На нашей модели оба аспекта отдельно не проверены; отключение TLS не рекомендуется как универсальное решение.

## 6. Сеть и границы доверия

Полная таблица пассивно наблюдённых binds — E10. Важные wildcard TCP endpoints:

| Порт | Bind observed | Предполагаемая роль | Уверенность |
|---|---|---|---|
| 2222 | IPv4 + IPv6 wildcard | Dropbear | runtime -p 2222 подтверждён, inode mapping не выполнялся |
| 5555 | IPv4 wildcard | ADB | upstream + процесс adbd, не вызов протокола |
| 8099 | IPv4 wildcard | YAM | upstream + yamd, не вызов API |
| 1961 | IPv6 wildcard | glagol | upstream, протокол не исследован |
| 7447 | IPv4 wildcard | Zenoh | upstream, не локальная атрибуция |
| 5081 | IPv4 wildcard | неизвестный сервис | не устанавливать назначение догадкой |
| 47747 | IPv6 wildcard | неизвестно | только наблюдение |

Wildcard binding не означает доступ из интернета или обход firewall. Не отправлялись управляющие запросы, не читались токены glagol. Секреты нельзя извлекать из devices.json ради «полноты архитектуры» без отдельного согласования.

## LED и реакции панели

Подтверждены 6 RGB-зон, 18 sysfs-каналов и отсутствие clock-узлов. Установленная радуга — подмена трёх native .led, не YAM-плагин. Связь касания центра с конкретным паттерном ещё неизвестна. См. [LED](led.md) и [E11–E13](evidence/005-led.md). Примеры с /dev/input/event1 из других моделей нельзя переносить: у нас среди имён input1 наблюдён детектор наушников, а не доказанная кнопка вызова.

## 7. Пробелы перед реализацией

- Точный build quasar, локальная launch-схема и параметры readiness.
- Контракты IPC и безопасное получение событий без избыточной записи речи.
- Версионная реализация YAM API и самообновления.
- Совместимость AirPlay/LLM кандидатов с Мини 2 и YAM 0.1.18.
- Подтверждённые внешние бэкапы и проверяемый rollback.

Ни один рецепт из этой страницы не разрешает агенту устанавливать пакеты, менять endpoints или останавливать maind.
