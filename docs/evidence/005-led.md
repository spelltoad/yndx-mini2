# E11–E13: LED, реакции панели и entrypoints

Дата исследования: 2026-10-27. Владелец выбрал LED-этап, уточнил жест: **центр панели / вызов Алисы**, и предпочтение **сохранять штатную Алису**. Разрешил чтение onboot.sh/run.sh/q, структурных сведений launch.json, LED-паттернов и пассивных LED/input-метаданных. Изменения, воспроизведение LED и чтение input-событий не разрешены и не выполнялись.

## E11 — локальные entrypoints

Полностью прочитаны `/system/vendor/quasar/onboot.sh`, `run.sh`, `q`, но не исполнены.

- onboot.sh start создаёт каталоги, меняет overcommit_memory, удаляет OTA-остатки, выставляет окружение и permissions, вызывает yio_iptables_init.sh, set_monotonic_time.sh, activate_adb.sh check, q save-last-monotonic-time и run.sh. Это объясняет, почему нельзя запускать его как диагностический скрипт.
- run.sh: cwd `/data/quasar`, CA_CERTIFICATES из системного каталога quasar; LD_LIBRARY_PATH `/system/vendor/quasar/libs`; ulimit -n 10240, -s 1024; nohup quasar_launcher2 с launch.json, вывод в `launcher2.out`; затем sleep 1.
- q stop: killall quasar_launcher2, ожидание, затем killall -9 maind и begemot. q restart вызывает stop/start.
- **q getprop не read-only:** вызывает maind --getprop с путём `/data/quasar/props`, читает и удаляет этот файл.
- q backend-dev/backend-prod изменяют флаг и перезапускают стек.

Вызванные дочерние скрипты не изучались полностью. Структура launch.json разрешена, но на этом LED-этапе глубже не извлекалась.

## E12 — LED/input metadata

`ls -1 /sys/class/leds` показывает ровно 18 узлов:
`mini2:{red,green,blue}:ring{1..6}` — это описательная запись множества, не исполняемая команда. У всех `max_brightness` = 255. Узлов clock в этом каталоге нет.

Прочитаны только имена input devices:

```text
/sys/class/input/input0/name: sar0_pad0
/sys/class/input/input1/name: AML-AUGESOUND Headphones
```

Назначение конкретных event codes и связь sar0_pad0 с жестом центра не проверены. `/dev/input/event*` не открывались; trigger/brightness не менялись. Наличие имени SAR не доказывает путь всех кнопок устройства.

Листинг `/system/vendor/quasar/ledpatterns` обнаружил `oknix/*.led` и `clock/*.binscled.zst`. Наличие clock-ассетов **не доказывает наличия часов**: владелец подтвердил отсутствие часов, sysfs clock-узлов здесь нет.

### Ключевой отрицательный результат

**Связь «касание центра → конкретный паттерн» не установлена.** Фиолетовые alice_pro_* и intonation_spotting — кандидаты только по содержимому; имя pro не доказывает применение к этой реакции, подписке или модели. Нельзя выбирать файл для замены только по цвету.

## Внешние источники

- https://hackalice.me/recipes/led/ — прочитано полностью. Общий формат .led и разные способы управления кольцом; Plum-trigger и clock-описание не переносить на наш экземпляр.
- https://raw.githubusercontent.com/nyakokitsu/yam/34c0c82fc4db5a61ee80d9c5aba8e2670a9cecc6/docs/PLUGIN_API.md — прочитано полностью. Permission led открывает set/off/play; input — отдельный permission с allowlist kernel device names; IPC control — отдельная возможность. Это документация API, **не аудит реализации LED arbitration**.

Ни Lua-плагины, ни led_util, ни записи sysfs не запускались. Полные логи и распознанная речь не читались.
